Configuración de Redes y Puertos en Vagrant

Domina el reenvío de puertos NAT, la creación de redes privadas Host-Only con IPs estáticas seguras y la conexión pública en modo puente (Bridged) para entornos multi-servidor.

1. Los Tres Modos de Red en Vagrant

Una máquina virtual aislada sin conectividad tiene poca utilidad práctica en Big Data o desarrollo. Vagrant abstrae la compleja pila de red de VirtualBox mediante 3 primitivas declarativas en el Vagrantfile:

Topología de Redes en Vagrant: NAT vs Privada vs Pública
Modo de Red Directiva Vagrant Visibilidad Host Visibilidad Red Local (LAN) Caso de Uso Típico
NAT + Forwarded Port forwarded_port Solo vía localhost:PUERTO ❌ No visible Desarrollo web puntual, APIs y microservicios.
Private Network private_network Directa vía IP estática (Host-Only) ❌ Aislada (Segura) Estándar docente: Clústeres Hadoop/Spark, réplicas y Ansible.
Public Network public_network Directa como un equipo más ✅ Sí (toda la oficina / aula) Demos compartidas, servidores para acceso de compañeros.

2. Reenvío de Puertos (Forwarded Ports)

Por defecto, la interfaz 1 de toda máquina Vagrant es un adaptador NAT gestionado por VirtualBox. Esto permite que la máquina descargue paquetes de Internet pero impide que el Host se conecte a sus servicios directamente. Para abrir un túnel, mapeamos puertos:

ruby — Mapeo de puertos en Vagrantfile 
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  # Mapeo simple: Puerto 80 de la VM expuesto en el puerto 8080 del host
  config.vm.network "forwarded_port", guest: 80, host: 8080

  # Mapeo seguro con auto-corrección de colisiones y binding exclusivo a localhost
  config.vm.network "forwarded_port", 
    guest: 5432, 
    host: 5432, 
    host_ip: "127.0.0.1", 
    auto_correct: true
end
✦ Parámetro 'host_ip: "127.0.0.1"' (Seguridad)

Por defecto, Vagrant escucha en 0.0.0.0 (todas las interfaces del Host). Si estás conectado a la Wi-Fi pública del instituto o cafetería, cualquiera podría atacar tu base de datos abierta. Al fijar host_ip: "127.0.0.1", el puerto solo es accesible desde tu propio ordenador.

✦ Parámetro 'auto_correct: true'

Si el puerto 8080 del Host ya está ocupado por otro contenedor Docker o servicio del sistema, Vagrant detectará el conflicto y asignará automáticamente el siguiente puerto libre (ej. 2200 o 8081), informándote en la consola sin abortar el arranque.

3. Red Privada (Private Network / Host-Only)

Es la configuración más robusta y la que utilizaremos en el 90% de las prácticas de Big Data. Crea un adaptador virtual Host-Only en VirtualBox, otorgando a la VM una dirección IP propia accesible desde tu terminal anfitrión sin necesidad de mapear decenas de puertos.

ruby — Asignación de IP estática en red privada 
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
  config.vm.hostname = "nodo-master"

  # Asignación de IP estática recomendada en rango estándar VirtualBox
  config.vm.network "private_network", ip: "192.168.56.10"
end
⚠️
¡ATENCIÓN CRÍTICA: Restricción de subred en VirtualBox 6.1.28+ y 7.x!
Muchos tutoriales antiguos de internet (e incluso apuntes de años anteriores) utilizan la IP 192.168.33.10. A partir de VirtualBox 6.1.28 y en todo VirtualBox 7.x, Oracle introdujo una política de seguridad estricta: los adaptadores host-only quedan restringidos por defecto a la subred 192.168.56.0/21.

Si usas 192.168.33.x sin configurar previamente el archivo /etc/vbox/networks.conf, Vagrant fallará con el error VERR_INTNET_FLT_IF_NOT_FOUND o denegará la creación del adaptador.
Regla de oro: En todas nuestras prácticas utilizaremos el rango 192.168.56.x (ejemplo: 192.168.56.10, 192.168.56.11, etc.).

4. Red Pública (Public Network / Modo Puente)

En este modo, la máquina virtual se comporta como un dispositivo físico independiente conectado directamente al switch o router de tu red local. Obtendrá una IP de la misma subred que tu ordenador físico (por ejemplo, 192.168.1.X).

ruby — Red pública por DHCP o IP estática 
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  # 1. DHCP automático (Vagrant preguntará qué tarjeta de red usar si hay varias)
  config.vm.network "public_network"

  # 2. Selección explícita de interfaz física para no pedir confirmación interactiva
  # En Windows suele llamarse: "Realtek Gaming 2.5GbE Family Controller" o "Intel(R) Wi-Fi"
  # En macOS: "en0: Wi-Fi (AirPort)"
  config.vm.network "public_network", bridge: "en0: Wi-Fi (AirPort)"

  # 3. IP Estática en la red local del aula/oficina
  config.vm.network "public_network", 
    ip: "192.168.1.185",
    netmask: "255.255.255.0",
    gateway: "192.168.1.1"
end

5. Vagrantfile de Producción: Combinando Puertos y Red Privada

En proyectos reales de Ingeniería de Datos es habitual combinar una red privada con IP estática (para comunicación interna y Ansible) y un puerto reenviado para probar un panel de administración web desde el navegador del Host:

ruby — Vagrantfile completo con red robusta 
# -*- mode: ruby -*-
# vi: set ft=ruby :

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
  config.vm.hostname = "datascience-srv"

  # 1. Red privada fija para SSH directo y gestión interna
  config.vm.network "private_network", ip: "192.168.56.20"

  # 2. Reenvío del puerto 8888 (Jupyter Notebook / Web UI) al localhost del anfitrión
  config.vm.network "forwarded_port", guest: 8888, host: 8888, host_ip: "127.0.0.1", auto_correct: true

  # 3. Reenvío del puerto PostgreSQL
  config.vm.network "forwarded_port", guest: 5432, host: 5433, host_ip: "127.0.0.1"

  # 4. Ajustes de proveedor
  config.vm.provider "virtualbox" do |vb|
    vb.name = "VM_DataScience_Redes"
    vb.memory = 2048
    vb.cpus = 2
  end
end

6. Comandos de Diagnóstico y Validación de Red

Una vez levantada la máquina con vagrant up, verifica el estado de las interfaces ejecutando las siguientes comprobaciones:

1

Inspeccionar las interfaces de red dentro de la VM

Entra por SSH a la máquina invitada y ejecuta el comando de Linux para listar direcciones IP y adaptadores:

bash — Dentro de la máquina virtual (vagrant ssh) 
# Listar adaptadores (eth0 será NAT, eth1 será la red privada)
ip -br addr show

# Salida esperada:
# lo               UNKNOWN        127.0.0.1/8 ::1/128 
# eth0             UP             10.0.2.15/24 (Adaptador NAT de Vagrant)
# eth1             UP             192.168.56.20/24 (Adaptador Host-Only Privado)
2

Verificar la conectividad desde tu máquina anfitriona (Host)

Abre PowerShell o Terminal en tu sistema físico y haz ping a la IP estática configurada:

bash — En tu terminal Host 
# Probar si el host llega a la máquina virtual
ping -c 3 192.168.56.20

# Conectar por SSH directamente sin pasar por 'vagrant ssh'
ssh vagrant@192.168.56.20
3

Comprobar puertos reenviados en el Host

Verifica si el puerto local está escuchando y listo para redirigir tráfico:

bash — Verificación de puertos locales 
# En Linux / macOS
lsof -i :8888

# En Windows PowerShell
Test-NetConnection -ComputerName 127.0.0.1 -Port 8888

✓ Checklist de Verificación de Red

  • Comprendidas las diferencias entre NAT, Red Privada (Host-Only) y Red Pública (Bridge).
  • Configurada la red privada en el rango compatible 192.168.56.x evitando el error de subred 192.168.33.x.
  • Añadido host_ip: "127.0.0.1" a los puertos sensibles para no exponerlos a la Wi-Fi local.
  • Validada la conectividad mediante ping 192.168.56.x e ip -br addr show.
