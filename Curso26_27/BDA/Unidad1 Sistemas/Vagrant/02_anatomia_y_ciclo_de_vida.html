Anatomía del Vagrantfile & Ciclo de Vida

Aprende a dominar el archivo de configuración en Ruby DSL, el repositorio Vagrant Cloud y los comandos fundamentales para controlar máquinas virtuales sin tocar la GUI.

1. Las Cajas (Boxes) y Vagrant Cloud

En lugar de descargar manualmente una ISO de instalación y pasar por el asistente de instalación de Ubuntu, Vagrant utiliza imágenes base empaquetadas llamadas Boxes.

Una box es un archivo comprimido que contiene un disco base en formato .vmdk o .vdi con un sistema operativo mínimo ya instalado, configurado con un usuario estándar vagrant (con privilegios de sudo sin contraseña) y las herramientas de integración del hipervisor (Guest Additions).

✦ Vagrant Cloud (El Repositorio Global)

Al igual que Docker Hub para contenedores, HashiCorp mantiene Vagrant Cloud, donde Canonical, Debian y la comunidad publican cajas oficiales.

  • ubuntu/jammy64 → Ubuntu 22.04 LTS (Oficial Canonical, 64-bit).
  • ubuntu/noble64 → Ubuntu 24.04 LTS (Oficial Canonical, 64-bit).
  • generic/ubuntu2204 → Variante genérica optimizada.
✦ Caché Local de Boxes

La primera vez que utilizas una box, Vagrant la descarga en tu disco local en la carpeta oculta ~/.vagrant.d/boxes. Las siguientes veces que crees máquinas con esa misma box, se clonará de forma instantánea sin gastar ancho de banda.

2. Anatomía de un Vagrantfile

El Vagrantfile es el archivo de texto plano que define la máquina virtual. Aunque utiliza la sintaxis de Ruby, no necesitas saber programar en Ruby: se estructura como un bloque de configuración declarativo muy limpio:

ruby — Estructura básica de un Vagrantfile 
# -*- mode: ruby -*-
# vi: set ft=ruby :

# Versión 2 de la API de configuración de Vagrant
Vagrant.configure("2") do |config|

  # 1. Imagen base del sistema operativo (Box oficial)
  config.vm.box = "ubuntu/jammy64"

  # 2. Nombre de host dentro de la máquina invitada
  config.vm.hostname = "servidor-bda"

  # 3. Proveedor: VirtualBox y parámetros de hardware
  config.vm.provider "virtualbox" do |vb|
    vb.name = "VM_Ubuntu_BigData"   # Nombre visible en VirtualBox GUI
    vb.memory = 2048                # Memoria RAM en Megabytes (2 GB)
    vb.cpus = 2                     # Cores de CPU virtuales
  end

end
💡
¿Por qué 'ubuntu/jammy64' en lugar de versiones antiguas?
Muchos tutoriales antiguos de internet siguen usando ubuntu/bionic64 (Ubuntu 18.04) o xenial64 (16.04). Esas versiones ya han alcanzado el fin de su soporte oficial (EOL). En Big Data y desarrollo moderno usamos siempre Ubuntu 22.04 LTS (Jammy) o Ubuntu 24.04 LTS (Noble) para tener compatibilidad total con Docker, Python 3.10+ y Java 17/21.

3. Creación del Primer Proyecto Paso a Paso

1

Crear un Directorio de Trabajo Limpio

Cada proyecto de Vagrant debe residir en su propia carpeta aislada:

bash / powershell 
mkdir mi_primer_vagrant && cd mi_primer_vagrant
2

Inicializar el Vagrantfile

El comando vagrant init genera un archivo Vagrantfile de plantilla apuntando a la box elegida:

bash / powershell 
vagrant init ubuntu/jammy64
3

Arrancar la Máquina Virtual (vagrant up)

Este es el comando maestro: descarga la box si no existe, crea la VM en VirtualBox, configura la red e inicia el sistema:

bash / powershell 
vagrant up
4

Conectarse por SSH a la Máquina

No necesitas abrir la consola gráfica de VirtualBox ni introducir contraseñas. Vagrant gestiona las llaves criptográficas automáticamente:

bash / powershell 
vagrant ssh

¡Ya estás dentro de tu servidor Ubuntu! Para salir y volver a tu anfitrión, escribe exit.

4. Diagrama del Ciclo de Vida y Comandos de Gestión

Transiciones de Estado de una Máquina Vagrant
Comando Qué hace exactamente Consumo de Recursos
vagrant status Muestra el estado actual de la máquina (running, poweroff, not created). Cero. Solo consulta el hipervisor.
vagrant halt Apagado limpio del sistema operativo (equivalente a shutdown -h now). Libera RAM y CPU. Mantiene el disco y los datos.
vagrant suspend Pausa la máquina y congela su estado en RAM/disco (muy rápido de reanudar con vagrant resume). Libera CPU pero ocupa espacio de swap/disco.
vagrant reload Reinicia la máquina y vuelve a leer el Vagrantfile para aplicar cambios de red o RAM. Reinicia el sistema operativo.
vagrant destroy -f Borra completamente la máquina virtual y sus discos en VirtualBox. Libera el 100% del almacenamiento SSD.

5. La Carpeta Oculta '.vagrant/' y la Regla de Oro de Git

Cuando ejecutas vagrant up, Vagrant crea automáticamente una carpeta oculta llamada .vagrant/ dentro del directorio de tu proyecto.

🛑
¡NUNCA subas '.vagrant/' a GitHub!
Dentro de .vagrant/ se guardan datos efímeros y específicos de tu máquina local: el UUID que vincula el proyecto con VirtualBox y la clave SSH privada generada (private_key). Si subes esta carpeta a un repositorio, romperás la máquina de tus compañeros de equipo y expondrás claves privadas.

Asegúrate de que todo repositorio que contenga un Vagrantfile incluya este archivo .gitignore:

gitignore 
# Directorio de estado interno de Vagrant (Obligatorio ignorar)
.vagrant/

# Archivos de log
*.log

✓ Lista de Comprobación del Capítulo

  • Directorio de proyecto creado e inicializado con vagrant init ubuntu/jammy64.
  • Máquina arrancada con vagrant up y sesión interactiva abierta con vagrant ssh.
  • Comprobados los comandos de parada y reinicio (vagrant halt y vagrant reload).
  • Archivo .gitignore configurado para evitar la subida accidental de .vagrant/.
