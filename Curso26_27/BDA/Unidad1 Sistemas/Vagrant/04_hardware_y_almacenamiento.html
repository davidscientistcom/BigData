Capítulo 04 · Dimensionamiento y Persistencia

Personalización de Hardware y Almacenamiento

Configura CPU y RAM mediante el proveedor VirtualBox, monta carpetas sincronizadas en tiempo real con permisos UNIX adecuados y amplía el almacenamiento para cargas de Big Data.

1. Asignación de Recursos de CPU y Memoria RAM

Por defecto, la mayoría de cajas descargadas desde Vagrant Cloud arrancan con especificaciones muy modestas (habitualmente 1 CPU virtual y 512 MB o 1024 MB de RAM). En el ciclo de Big Data, ejecutar procesos de Spark, contenedores Docker o motores de base de datos exige dimensionar los recursos mediante el bloque de configuración del proveedor:

ruby — Configuración de hardware en Vagrantfile 
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
  config.vm.hostname = "motor-analitica"

  # Bloque de configuración específico para VirtualBox
  config.vm.provider "virtualbox" do |vb|
    vb.name = "VM_BigData_Worker_01"   # Nombre visible en la lista de VirtualBox GUI
    vb.memory = 4096                   # Memoria RAM en Megabytes (4 GB)
    vb.cpus = 2                        # Número de núcleos vCPU asignados
    vb.gui = false                     # Ejecución sin ventana gráfica (Headless, ahorra CPU)

    # Parámetros avanzados vía VBoxManage (ej: Virtualización anidada para Docker/KVM)
    vb.customize ["modifyvm", :id, "--nested-hw-virt", "on"]
    
    # Habilitar soporte de portapapeles y arrastrar si se usara GUI
    # vb.customize ["modifyvm", :id, "--clipboard-mode", "bidirectional"]
  end
end
💡
Consejo de SysAdmin: No asfixies el Sistema Anfitrión
Como norma general, nunca asignes a tus máquinas virtuales más del 50% de la RAM física ni más del 50% de los hilos de CPU de tu ordenador físico. Si tu portátil tiene 16 GB de RAM, puedes asignar hasta 8 GB a tu máquina invitada; de lo contrario, el sistema operativo anfitrión (Windows/macOS) sufrirá congelaciones y "swapping" severo de disco.

2. Carpetas Sincronizadas (Synced Folders)

Una de las mayores ventajas de Vagrant sobre las máquinas virtuales convencionales es la eliminación de la necesidad de transferir archivos por FTP o pendrives. Vagrant enlaza de forma bidireccional carpetas de tu ordenador físico con directorios dentro de la máquina virtual.

Mapeo Bidireccional de Carpetas Compartidas
✦ La carpeta por defecto: '/vagrant'

Sin escribir una sola línea extra en tu Vagrantfile, el directorio donde se ubica dicho archivo se monta automáticamente dentro de la máquina invitada en la ruta /vagrant.

✦ Sincronización en Tiempo Real

Cualquier fichero que guardes en tu ordenador anfitrión usando VS Code aparece en la máquina virtual en milisegundos, permitiendo programar en tu interfaz habitual y compilar o procesar dentro de Linux.

Definición de Carpetas Sincronizadas Personalizadas

Podemos mapear directorios adicionales o alterar permisos UNIX de propietario y lectura/escritura:

ruby — Opciones avanzadas de synced_folder 
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  # 1. Deshabilitar la carpeta por defecto /vagrant si no la necesitas por seguridad
  # config.vm.synced_folder ".", "/vagrant", disabled: true

  # 2. Mapeo personalizado: ./data en el host -> /mnt/datasets en la VM
  config.vm.synced_folder "./data", "/mnt/datasets"

  # 3. Mapeo con permisos explícitos para servidores web o bases de datos
  # fmode = permisos de ficheros (664) | dmode = permisos de directorios (775)
  config.vm.synced_folder "./src", "/var/www/html",
    owner: "vagrant",
    group: "vagrant",
    mount_options: ["dmode=775", "fmode=664"]
end

3. Almacenamiento y Redimensionamiento del Disco

Las cajas oficiales de Ubuntu en Vagrant Cloud se publican típicamente con un disco base de 10 GB a 20 GB. Para tareas de Big Data (donde los archivos Parquet, bases de datos PostgreSQL o logs superan fácilmente esta capacidad), nos encontramos pronto con el temido error No space left on device.

Método 1: Redimensionamiento Nativo (Vagrant 2.2.19+)

En versiones recientes de Vagrant, ya es posible declarar el tamaño del disco principal directamente mediante la directiva config.vm.disk:

ruby — Redimensionamiento nativo en Vagrantfile 
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  # Redimensionar el disco principal primario a 50 Gigabytes
  config.vm.disk :disk, size: "50GB", primary: true

  config.vm.provider "virtualbox" do |vb|
    vb.memory = 4096
    vb.cpus = 2
  end
end

Método 2: Plugin Clásico 'vagrant-disksize' (Máxima Compatibilidad)

Si trabajas en sistemas donde la directiva nativa no esté activa o uses cajas de terceros, el plugin vagrant-disksize es el estándar histórico de la industria:

1

Instalar el plugin en el sistema anfitrión

Ejecuta en tu terminal anfitriona (solo hay que hacerlo una vez):

bash — Instalación del plugin 
vagrant plugin install vagrant-disksize
2

Declarar el tamaño en el Vagrantfile

Añade la directiva config.disksize.size:

ruby — Uso del plugin vagrant-disksize 
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  # Asignar 60 GB de disco mediante el plugin
  config.disksize.size = "60GB"
end
ℹ️
¿Qué pasa con la partición en Ubuntu Jammy?
En sistemas antiguos, ampliar el disco virtual obligaba al alumno a ejecutar gparted o fdisk para extender la partición. En las cajas modernas ubuntu/jammy64 y noble64, el servicio cloud-init detecta el crecimiento del disco en el primer arranque y ejecuta automáticamente growpart y resize2fs, entregándote el disco expandido al 100% sin intervención manual.

4. Vagrantfile Completo: Estación de Ingeniería de Datos

Unificamos hardware avanzado, carpetas compartidas y disco ampliado en una plantilla lista para producción:

ruby — Vagrantfile completo optimizado para datos 
# -*- mode: ruby -*-
# vi: set ft=ruby :

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
  config.vm.hostname = "data-station"

  # 1. Almacenamiento en disco (50 GB)
  config.vm.disk :disk, size: "50GB", primary: true

  # 2. Red privada estática
  config.vm.network "private_network", ip: "192.168.56.30"

  # 3. Sincronización de datasets locales
  config.vm.synced_folder "./datasets", "/opt/datasets",
    owner: "vagrant",
    group: "vagrant"

  # 4. Asignación de recursos en VirtualBox
  config.vm.provider "virtualbox" do |vb|
    vb.name = "VM_BigData_DataStation"
    vb.memory = 4096
    vb.cpus = 2
    vb.customize ["modifyvm", :id, "--nested-hw-virt", "on"]
  end
end

5. Verificación de Recursos desde la Terminal

Arranca la máquina con vagrant up (o si ya existía y cambiaste el hardware, usa vagrant reload) y valida los recursos:

bash — Comandos de comprobación dentro de la VM 
# 1. Comprobar memoria RAM libre y asignada
free -h

# 2. Comprobar núcleos de CPU disponibles
nproc
lscpu | grep "CPU(s):"

# 3. Comprobar tamaño real de las particiones montadas
df -h /

# 4. Comprobar que la carpeta sincronizada está montada y operativa
ls -la /opt/datasets/
touch /opt/datasets/prueba_host.txt
# ¡Comprueba ahora en tu explorador de archivos del host que el fichero apareció!

✓ Checklist de Verificación de Recursos

  • Configurados vb.memory y vb.cpus sin exceder el 50% de las capacidades del equipo físico.
  • Comprobada la carpeta compartida por defecto /vagrant y personalizadas nuevas carpetas con permisos de usuario.
  • Dimensionado el almacenamiento a 50GB mediante config.vm.disk o el plugin vagrant-disksize.
  • Verificado con df -h y free -h que el sistema operativo reconoce los recursos asignados.
