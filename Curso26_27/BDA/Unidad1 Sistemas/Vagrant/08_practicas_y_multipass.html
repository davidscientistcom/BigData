Prácticas Guiadas de Laboratorio y Multipass

Aplica todo lo aprendido mediante tres proyectos reales de ingeniería de sistemas y descubre Multipass, la herramienta cloud-native de Canonical basada en hipervisores nativos y cloud-init.

1. Lab 1: Servidor Web Nginx + PostgreSQL Aprovisionado

Objetivo del proyecto: Crear una infraestructura reproducible que levante una máquina virtual con Ubuntu 22.04 LTS, instale Nginx y PostgreSQL de forma desatendida, exponga sus puertos de manera segura hacia el anfitrión y monte un directorio de datos compartido.

ruby — Vagrantfile del Lab 1 
# -*- mode: ruby -*-
# vi: set ft=ruby :

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
  config.vm.hostname = "lab1-datasrv"

  # 1. Red privada estática en subred VirtualBox 7
  config.vm.network "private_network", ip: "192.168.56.50"

  # 2. Reenvío de puertos a localhost
  config.vm.network "forwarded_port", guest: 80, host: 8080, host_ip: "127.0.0.1", auto_correct: true
  config.vm.network "forwarded_port", guest: 5432, host: 5433, host_ip: "127.0.0.1", auto_correct: true

  # 3. Carpeta sincronizada para scripts SQL y datasets
  config.vm.synced_folder "./sql_data", "/opt/sql_data",
    owner: "vagrant",
    group: "vagrant"

  # 4. Recursos de VirtualBox
  config.vm.provider "virtualbox" do |vb|
    vb.name = "VM_Lab1_DataServer"
    vb.memory = 2048
    vb.cpus = 2
  end

  # 5. Aprovisionamiento Shell externo
  config.vm.provision "shell", path: "provision_lab1.sh"
end
bash — provision_lab1.sh 
#!/usr/bin/env bash
set -e

echo "==> [Paso 1] Actualizando repositorios del sistema..."
export DEBIAN_FRONTEND=noninteractive
apt-get update -y

echo "==> [Paso 2] Instalando Nginx y PostgreSQL..."
apt-get install -y nginx postgresql postgresql-contrib

echo "==> [Paso 3] Configurando Nginx con mensaje personalizado..."
cat << 'EOF' > /var/www/html/index.html


Lab 1 BDA

  
✓ Servidor Web Nginx Operativo

  
Entorno aprovisionado exitosamente con Vagrant IaC.



EOF
systemctl restart nginx

echo "==> [Paso 4] Configurando usuario de PostgreSQL para el curso..."
sudo -u postgres psql -c "ALTER USER postgres PASSWORD 'vagrant';"
sudo -u postgres createdb bda_analytics || true

echo "==> ¡Servidor aprovisionado y listo para pruebas!"

2. Lab 2: Clúster de Datos Master/Worker con DNS Interno

Objetivo del proyecto: Diseñar un clúster distribuido de 3 nodos (1 Master y 2 Workers). Cada nodo debe tener conectividad por red privada y resolución de nombres cruzada en /etc/hosts para que puedan comunicarse por su nombre (ej. ping spark-worker-1).

ruby — Vagrantfile del Clúster Distribuido 
# -*- mode: ruby -*-
# vi: set ft=ruby :

NODOS = [
  { name: "master",  ip: "192.168.56.10", cpus: 2, ram: 2048 },
  { name: "worker1", ip: "192.168.56.11", cpus: 1, ram: 1024 },
  { name: "worker2", ip: "192.168.56.12", cpus: 1, ram: 1024 }
]

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  NODOS.each do |nodo|
    config.vm.define nodo[:name] do |node|
      node.vm.hostname = nodo[:name]
      node.vm.network "private_network", ip: nodo[:ip]

      node.vm.provider "virtualbox" do |vb|
        vb.name = "Cluster_#{nodo[:name].capitalize}"
        vb.memory = nodo[:ram]
        vb.cpus = nodo[:cpus]
      end

      # Script común para resolver nombres en /etc/hosts
      node.vm.provision "shell", inline: <<-SHELL
        grep -qxF "192.168.56.10 master" /etc/hosts || echo "192.168.56.10 master" >> /etc/hosts
        grep -qxF "192.168.56.11 worker1" /etc/hosts || echo "192.168.56.11 worker1" >> /etc/hosts
        grep -qxF "192.168.56.12 worker2" /etc/hosts || echo "192.168.56.12 worker2" >> /etc/hosts
      SHELL
    end
  end
end
💡
Prueba de Conectividad Cruzada del Lab 2:
Una vez levantado el clúster con vagrant up, entra al nodo maestro con vagrant ssh master y haz ping a los trabajadores usando directamente sus nombres de host: 
ping -c 2 worker1
ping -c 2 worker2
¡Comprobarás que responden en 192.168.56.11 y .12 con cero pérdida de paquetes!

3. Lab 3: Empaquetar y Distribuir una Box Personalizada

Objetivo: Configurar un entorno con herramientas complejas (Docker, Python 3, librerías) y exportarlo como un fichero .box que un compañero pueda añadir con vagrant box add sin descargar nada de internet.

1

Limpiar la máquina antes del empaquetado (Para reducir tamaño)

Entra por SSH a la máquina y vacía las cachés de apt y ficheros temporales:

sudo apt-get clean
sudo rm -rf /tmp/* /var/tmp/*
# Opcional: Rellenar el espacio libre con ceros para comprimir el disco virtual
sudo dd if=/dev/zero of=/EMPTY bs=1M || sudo rm -f /EMPTY
exit
2

Apagar y empaquetar con el CLI de Vagrant

Desde el host en la carpeta del Vagrantfile:

vagrant halt
vagrant package --output ubuntu_bda_custom.box
3

Probar la nueva box en una carpeta limpia

En cualquier otro equipo o carpeta:

vagrant box add bda-base ./ubuntu_bda_custom.box
vagrant init bda-base
vagrant up

4. Alternativa Cloud-Native: Tutorial de Multipass (Canonical)

En los últimos años, Canonical (la creadora de Ubuntu) ha desarrollado Multipass, una alternativa moderna a la combinación Vagrant + VirtualBox diseñada específicamente para entornos Cloud y arquitecturas Apple Silicon / WSL2.

Comparativa de Arquitectura: Vagrant+VirtualBox vs Multipass Nativo
Característica Vagrant + VirtualBox Multipass (Canonical)
Tipo de Hipervisor Tipo 2 (Hosted, mayor consumo de CPU/RAM). Nativo (Hyper-V en Win, KVM en Linux, Hypervisor.framework en Mac).
Sistemas Operativos Cualquier SO (Ubuntu, Debian, CentOS, Windows). Especializado exclusivamente en imágenes oficiales Ubuntu.
Aprovisionamiento Ruby DSL (Vagrantfile) + Shell / Ansible. cloud-init (YAML), estándar universal de AWS/Azure/GCP.
Velocidad de Arranque 40 – 90 segundos. 10 – 25 segundos (rendimiento casi nativo).

Instalación de Multipass

bash — Instalación según plataforma 
# En Windows (PowerShell Administrador vía winget)
winget install Canonical.Multipass

# En Linux (mediante Snap)
sudo snap install multipass

# En macOS (mediante Homebrew)
brew install --cask multipass

Comandos Fundamentales de Multipass (Cheat Sheet)

bash — CLI de Multipass 
# 1. Ver versiones de Ubuntu disponibles
multipass find

# 2. Lanzar una máquina virtual en 20 segundos
multipass launch --name nodo-datos --cpus 2 --memory 2G --disk 15G 24.04

# 3. Listar máquinas e IPs asignadas
multipass list

# 4. Entrar por SSH con sesión interactiva
multipass shell nodo-datos

# 5. Ejecutar un comando remoto sin entrar a la shell
multipass exec nodo-datos -- uname -a

# 6. Montar una carpeta del host en la máquina
multipass mount ./datos nodo-datos:/opt/datos

# 7. Apagar y purgar máquinas
multipass stop nodo-datos
multipass delete nodo-datos
multipass purge

Aprovisionamiento Cloud-Native con 'cloud-init'

En lugar de un Vagrantfile en Ruby, Multipass utiliza cloud-init mediante un archivo YAML estándar de la industria Cloud:

yaml — cloud-config.yaml para Multipass 
#cloud-config
package_update: true
package_upgrade: true
packages:
  - curl
  - git
  - python3-pip
  - docker.io

runcmd:
  - systemctl enable --now docker
  - usermod -aG docker ubuntu
  - echo "
Multipass Cloud-Init BDA
" > /var/www/html/index.html

Para lanzar la máquina aprovisionada con ese archivo:

multipass launch --name srv-cloud --cloud-init cloud-config.yaml 24.04
