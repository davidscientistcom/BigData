Aprovisionamiento Automatizado en Vagrant

Aprende a inyectar scripts de Shell, instalar paquetes, configurar servicios del sistema y garantizar la idempotencia para que cualquier miembro del equipo levante un entorno idéntico con un solo comando.

1. ¿Qué es el Provisioning y por qué es Esencial?

Cuando descargas una box oficial de Ubuntu, obtienes un sistema operativo "virgen": contiene la base de Linux, pero carece de Docker, Python, bases de datos o librerías de análisis. Entrar manualmente por SSH a teclear apt-get install en cada máquina rompe por completo el principio de Infraestructura como Código (IaC).

El Aprovisionamiento (Provisioning) es el proceso automático mediante el cual Vagrant ejecuta scripts o herramientas de configuración tan pronto como la máquina virtual finaliza su arranque inicial.

Flujo de Aprovisionamiento en Vagrant

2. Tipos de Aprovisionamiento en Shell

Vagrant soporta múltiples herramientas (Ansible, Chef, Puppet, Docker), pero el provisionador más universal, directo y rápido de aprender es el Shell Provisioner. Existen dos modalidades:

✦ Modo Inline (Directo en el Vagrantfile)

Ideal para configuraciones cortas (2 a 10 líneas), actualizar repositorios o instalar paquetes esenciales.

Vagrant.configure("2") do |config|
  config.vm.provision "shell", inline: <<-SHELL
    apt-get update
    apt-get install -y git curl
  SHELL
end
✦ Modo Script Externo (Recomendado)

Permite desacoplar el código de configuración en un archivo .sh modular que puedes versionar con Git y depurar independientemente.

Vagrant.configure("2") do |config|
  config.vm.provision "shell", path: "scripts/bootstrap.sh"
end

Control de Ejecución: 'run: "once"' vs 'run: "always"'

Por defecto, los scripts de aprovisionamiento se ejecutan una sola vez durante el primer vagrant up. Si reinicias la máquina con vagrant reload, Vagrant se salta el provisioner para no perder tiempo. Sin embargo, puedes forzar el comportamiento:

Parámetro Comportamiento Cuándo Utilizarlo
run: "once" (Por defecto) Solo se ejecuta la primera vez que se crea la máquina virtual. Instalación de paquetes de sistema (Python, PostgreSQL, Docker).
run: "always" Se ejecuta en CADA arranque o reinicio (vagrant up y vagrant reload). Sincronizar la hora del sistema, montar volúmenes de red o arrancar servicios personalizados.
privileged: false Ejecuta el script como el usuario normal vagrant en lugar de root. Instalación de entornos virtuales de Python (venv) o configuración de .bashrc del usuario.

3. Buenas Prácticas Críticas de SysAdmin en Shell Scripts

Aprovisionar máquinas virtuales desatendidas requiere seguir tres reglas de oro para evitar que el proceso se quede congelado esperando respuestas humanas:

1

Desactivar diálogos interactivos: 'DEBIAN_FRONTEND=noninteractive'

En Ubuntu/Debian, paquetes como tzdata o actualizaciones del kernel intentan abrir una ventana azul interactiva solicitando pulsar Enter. En una terminal automatizada de Vagrant, esto congelará el comando indefinidamente:

export DEBIAN_FRONTEND=noninteractive
apt-get update -y
apt-get upgrade -y -o Dpkg::Options::="--force-confdef" -o Dpkg::Options::="--force-confold"
2

Diseñar scripts Idempotentes (Capaces de repetirse sin romper)

Un script idempotente produce el mismo resultado sin importar cuántas veces se ejecute. Comprueba siempre si un servicio o archivo ya existe antes de añadirlo:

# ❌ MAL: Añade la línea una y otra vez cada vez que se aprovisiona
echo "alias ll='ls -la'" >> /home/vagrant/.bashrc

# ✅ BIEN: Idempotente (solo añade la línea si no existe previamente)
grep -qxF "alias ll='ls -la'" /home/vagrant/.bashrc || echo "alias ll='ls -la'" >> /home/vagrant/.bashrc
3

Habilitar y arrancar servicios con 'systemctl'

Asegúrate de que los servicios instalados queden habilitados para iniciarse automáticamente tras futuros reinicios:

systemctl enable --now docker
systemctl enable --now nginx

4. Caso Práctico: Aprovisionamiento de Pila de Datos (Python + PostgreSQL + Docker)

A continuación creamos una infraestructura completa con un script externo modular:

ruby — Vagrantfile 
# -*- mode: ruby -*-
# vi: set ft=ruby :

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
  config.vm.hostname = "srv-analytics"

  config.vm.network "private_network", ip: "192.168.56.40"
  config.vm.network "forwarded_port", guest: 80, host: 8080, host_ip: "127.0.0.1"

  config.vm.provider "virtualbox" do |vb|
    vb.name = "VM_Analytics_Provisioned"
    vb.memory = 3072
    vb.cpus = 2
  end

  # Script de aprovisionamiento en archivo externo
  config.vm.provision "shell", path: "bootstrap.sh"
end
bash — bootstrap.sh (En la misma carpeta del Vagrantfile) 
#!/usr/bin/env bash
set -e # Abortar script si algún comando devuelve error

echo "==> [1/4] Actualizando índices de paquetes..."
export DEBIAN_FRONTEND=noninteractive
apt-get update -y

echo "==> [2/4] Instalando utilidades básicas y entorno Python..."
apt-get install -y \
    curl \
    wget \
    git \
    htop \
    python3-pip \
    python3-venv \
    nginx

echo "==> [3/4] Configurando página web informativa..."
echo "
Servidor de Analitica BDA listo
Aprovisionado automaticamente con Vagrant IaC.
" > /var/www/html/index.html
systemctl restart nginx

echo "==> [4/4] Añadiendo usuario vagrant al grupo docker..."
# Si se instala docker: usermod -aG docker vagrant

echo "==> ¡Aprovisionamiento completado con éxito!"

5. Gestión de Aprovisionamiento en Terminal (CLI)

¿Qué pasa si modificas tu script bootstrap.sh y quieres aplicarlo a una máquina que ya está funcionando sin destruirla?

bash — Comandos para relanzar aprovisionamiento 
# 1. Re-ejecutar aprovisionamiento en una máquina encendida (en caliente)
vagrant provision

# 2. Reiniciar la máquina virtual y forzar la ejecución del aprovisionamiento
vagrant reload --provision

# 3. Arrancar una máquina apagada forzando aprovisionamiento aunque ya existiera
vagrant up --provision

✓ Checklist de Aprovisionamiento

  • Entendida la diferencia entre aprovisionamiento en línea (inline) y archivo externo (path).
  • Incluido export DEBIAN_FRONTEND=noninteractive y el flag -y en comandos apt.
  • Garantizada la idempotencia en los scripts para permitir ejecuciones sucesivas con vagrant provision.
  • Comprobada la recarga y re-aprovisionamiento mediante vagrant reload --provision.
