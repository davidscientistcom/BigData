Entornos Multi-Máquina y Clústeres

Aprende a definir clústeres completos con topologías Master/Worker, balanceadores de carga y bases de datos en un único Vagrantfile, aprovechando bucles dinámicos en Ruby y control granular por CLI.

1. De la Máquina Aislada al Clúster Distribuido

En el mundo real del Big Data y la analítica empresarial, ningún servicio de envergadura se ejecuta en un único servidor. Trabajamos con sistemas distribuidos: Apache Spark, clústeres de Hadoop, réplicas de bases de datos PostgreSQL o arquitecturas web de tres capas.

Configurar esto manualmente en VirtualBox requeriría crear cada máquina a mano, fijar adaptadores, sincronizar IPs y verificar nombres de host uno por uno. Con Vagrant, declaramos la topología completa en un único archivo Vagrantfile y levantamos todo el clúster con un solo comando:

Topología de Clúster de Datos: Master + Workers en Red Privada

2. La Directiva 'config.vm.define'

Para declarar múltiples máquinas dentro del mismo bloque Vagrant.configure("2"), utilizamos la llamada config.vm.define "nombre_maquina". Todo lo que esté fuera de este bloque se hereda como configuración común para todas las instancias:

ruby — Clúster básico de 2 nodos 
Vagrant.configure("2") do |config|
  # Configuración global común a todas las máquinas
  config.vm.box = "ubuntu/jammy64"

  # 1. Definición del Servidor Web
  config.vm.define "web" do |web|
    web.vm.hostname = "web-server"
    web.vm.network "private_network", ip: "192.168.56.11"
    web.vm.network "forwarded_port", guest: 80, host: 8080, host_ip: "127.0.0.1"
    
    web.vm.provider "virtualbox" do |vb|
      vb.name = "VM_Cluster_Web"
      vb.memory = 1536
      vb.cpus = 1
    end
  end

  # 2. Definición del Servidor de Base de Datos
  config.vm.define "db" do |db|
    db.vm.hostname = "db-server"
    db.vm.network "private_network", ip: "192.168.56.12"
    
    db.vm.provider "virtualbox" do |vb|
      vb.name = "VM_Cluster_DB"
      vb.memory = 2048
      vb.cpus = 2
    end
  end
end

3. Escalabilidad Dinámica: Bucles en Ruby

¿Qué ocurre si necesitas un clúster de 3 o 5 nodos trabajadores para procesar datos? Copiar y pegar bloques de código idénticos es propenso a errores y viola el principio DRY (Don't Repeat Yourself). Como el Vagrantfile es código Ruby estándar, podemos usar bucles iterativos:

ruby — Creación de Workers dinámicos con bucle Ruby 
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  # Nodo Maestro Único
  config.vm.define "master" do |master|
    master.vm.hostname = "spark-master"
    master.vm.network "private_network", ip: "192.168.56.10"
    master.vm.provider "virtualbox" do |vb|
      vb.name = "Spark_Master"
      vb.memory = 2048
      vb.cpus = 2
    end
  end

  # Generación iterativa de Nodos Trabajadores (worker1, worker2, worker3)
  NUM_WORKERS = 2
  (1..NUM_WORKERS).each do |i|
    config.vm.define "worker#{i}" do |worker|
      worker.vm.hostname = "spark-worker-#{i}"
      # Asigna IPs consecutivas: 192.168.56.11, 192.168.56.12, etc.
      worker.vm.network "private_network", ip: "192.168.56.#{10 + i}"
      
      worker.vm.provider "virtualbox" do |vb|
        vb.name = "Spark_Worker_#{i}"
        vb.memory = 1024
        vb.cpus = 1
      end
    end
  end
end

4. Control Granular desde la CLI de Vagrant

Cuando trabajas con múltiples máquinas, los comandos de Vagrant cambian ligeramente: ahora puedes operar sobre todo el clúster a la vez o apuntar a un nodo específico.

Comando Ámbito Descripción
vagrant status Todo el clúster Muestra una tabla con el estado de cada máquina (running, poweroff, etc.).
vagrant up Todo el clúster Arranca todas las máquinas definidas en el orden en que aparecen en el archivo.
vagrant up worker1 Máquina individual Arranca exclusivamente la máquina worker1 sin encender las demás.
vagrant ssh master Máquina individual ¡Obligatorio! En multi-máquina debes indicar el nombre del host al que deseas conectar.
vagrant halt web Máquina individual Apaga de forma ordenada el servidor web.
vagrant destroy -f worker2 Máquina individual Destruye solo el nodo worker2 sin tocar el resto del clúster.

5. Caso Práctico: Balanceador Nginx + 2 Servidores Backend

En este escenario, simulamos una infraestructura de alta disponibilidad: un balanceador Nginx en la IP 192.168.56.10 recibe las peticiones y las distribuye mediante Round Robin entre dos servidores web internos:

ruby — Vagrantfile completo de Alta Disponibilidad 
# -*- mode: ruby -*-
# vi: set ft=ruby :

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  # 1. Balanceador de Carga Nginx
  config.vm.define "lb" do |lb|
    lb.vm.hostname = "load-balancer"
    lb.vm.network "private_network", ip: "192.168.56.10"
    lb.vm.network "forwarded_port", guest: 80, host: 8080, host_ip: "127.0.0.1"
    
    lb.vm.provider "virtualbox" do |vb|
      vb.name = "Cluster_LB"
      vb.memory = 1024
      vb.cpus = 1
    end

    lb.vm.provision "shell", inline: <<-SHELL
      export DEBIAN_FRONTEND=noninteractive
      apt-get update -y && apt-get install -y nginx
      
      cat << 'EOF' > /etc/nginx/sites-available/default
      upstream backends {
          server 192.168.56.11:80;
          server 192.168.56.12:80;
      }
      server {
          listen 80;
          location / {
              proxy_pass http://backends;
              proxy_set_header Host $host;
              proxy_set_header X-Real-IP $remote_addr;
          }
      }
EOF
      systemctl restart nginx
    SHELL
  end

  # 2. Servidores Web de Backend
  (1..2).each do |i|
    config.vm.define "web#{i}" do |web|
      web.vm.hostname = "web-node-#{i}"
      web.vm.network "private_network", ip: "192.168.56.#{10 + i}"
      
      web.vm.provider "virtualbox" do |vb|
        vb.name = "Cluster_Web_#{i}"
        vb.memory = 1024
        vb.cpus = 1
      end

      web.vm.provision "shell", inline: <<-SHELL
        export DEBIAN_FRONTEND=noninteractive
        apt-get update -y && apt-get install -y nginx
        echo "
Respuesta desde NODO WEB #{i}
IP: 192.168.56.#{10 + i}
" > /var/www/html/index.html
        systemctl restart nginx
      SHELL
    end
  end
end
💡
¿Cómo probar el Balanceador de Carga?
Una vez levantado con vagrant up, abre tu navegador en el Host y navega a http://localhost:8080. Al pulsar Ctrl+F5 repetidas veces para refrescar sin caché, verás cómo el texto va alternando entre "Respuesta desde NODO WEB 1" y "Respuesta desde NODO WEB 2". ¡Has creado un clúster de alta disponibilidad en minutos!

6. Distribución de Entornos: 'vagrant package'

¿Qué pasa si configuras un entorno complejo con herramientas analíticas preinstaladas y quieres compartirlo con tus compañeros del aula sin que tengan que esperar 30 minutos descargando paquetes?

Vagrant permite "congelar" y empaquetar una máquina virtual en un archivo package.box independiente:

bash — Empaquetado y distribución de cajas 
# 1. Apagar la máquina que queremos empaquetar
vagrant halt web1

# 2. Empaquetar la VM en un fichero package.box
vagrant package web1 --output bda_ubuntu_custom.box

# 3. Tu compañero puede registrar tu box local en su ordenador con:
vagrant box add bda-custom ./bda_ubuntu_custom.box

# 4. Y usarla en su Vagrantfile con:
# config.vm.box = "bda-custom"

  • Implementado bucles de Ruby (1..N).each para escalar nodos sin duplicar código.
  • Dominado el uso de vagrant ssh [nombre] y control selectivo con vagrant up/halt.
  • Conocido el proceso de empaquetado de imágenes con vagrant package.
