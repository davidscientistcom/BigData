Extractor Concurrente con Rate Limiting y Métricas

Consolidación de patrones: arquitectura de workers con colas, agregación métrica protegida contra condiciones de carrera y tolerancia a fallos transitorios.

E5.0: Pipeline de Extracción Concurrente y Agregación Métrica

Objetivo Técnico: Desarrollar un sistema de extracción asíncrono para ingesta de datos a escala. El componente debe procesar un lote de 30 URLs concurrentes utilizando un pool fijo de workers, tolerar errores aleatorios de red (HTTP 500/404) y registrar métricas globales de latencia y estado mediante exclusión mutua.

python — e5_0_crawler_concurrente.py 
import asyncio
import random
import time

# Estructura de métricas compartida
metricas = {
    "exitosos": 0,
    "fallidos": 0,
    "latencia_total": 0.0
}
mutex_metricas = asyncio.Lock()

async def worker_extractor(id_worker: str, cola: asyncio.Queue):
    global metricas
    while True:
        url = await cola.get()
        t_inicio = time.time()
        
        # Simulación de latencia de red variable
        latencia = random.uniform(0.1, 0.8)
        await asyncio.sleep(latencia)
        
        # Simulación de fallos transitorios de red (tasa de error 10%)
        es_exitoso = random.random() > 0.10
        
        # Actualización de estado compartido bajo exclusión mutua estricta
        async with mutex_metricas:
            metricas["latencia_total"] += latencia
            if es_exitoso:
                metricas["exitosos"] += 1
                status = "HTTP 200"
            else:
                metricas["fallidos"] += 1
                status = "HTTP 503"
            print(f"[{id_worker}] {url} -> {status} ({latencia:.2f}s)")
            
        cola.task_done()

async def main():
    t_global = time.time()
    cola = asyncio.Queue()
    num_workers = 5
    total_recursos = 30

    # 1. Encolado de recursos objetivo
    for i in range(1, total_recursos + 1):
        cola.put_nowait(f"https://api.empresa.internal/v1/records/{i:05d}")

    # 2. Despliegue del pool acotado de workers
    workers = [
        asyncio.create_task(worker_extractor(f"W-{i:02d}", cola))
        for i in range(1, num_workers + 1)
    ]

    print(f"[ORCHESTRATOR] Procesando {total_recursos} peticiones con pool concurrente de {num_workers} workers...")
    
    # 3. Sincronización de vaciado de cola
    await cola.join()

    # 4. Parada limpia de workers
    for w in workers:
        w.cancel()

    # 5. Consolidación analítica final
    duracion = time.time() - t_global
    print("
" + "=" * 50)
    print("REPORTE DE INGESTA CONCURRENTE")
    print("=" * 50)
    print(f"Tiempo total transcurrido:    {duracion:.2f} segundos")
    print(f"Peticiones exitosas:          {metricas['exitosos']}")
    print(f"Peticiones fallidas:          {metricas['fallidos']}")
    print(f"Throughput efectivo:          {total_recursos / duracion:.1f} req/s")
    print("=" * 50)

if __name__ == "__main__":
    asyncio.run(main())
Evaluación de Rendimiento: En un enfoque síncrono secuencial clásico, 30 peticiones con una latencia media de 0.45s habrían requerido aproximadamente 13.5 segundos. Mediante este pipeline asíncrono con 5 workers, el lote completo se procesa en ~2.7 segundos, multiplicando el throughput por un factor de 5x sin el sobrecoste de memoria ni cambios de contexto de 30 hilos del sistema operativo.
