Bloque 3: Primitivas de Sincronización

La concurrencia trae un problema: varias tareas queriendo el mismo recurso a la vez causan "Condiciones de Carrera". Aprende a poner Semáforos y Candados.

E3.0: La Condición de Carrera

Objetivo: Forzar un fallo. Cuando varias corrutinas leen y escriben a la misma variable sin protección, pueden sobrescribirse mutuamente si hay un cambio de contexto (await) en medio de la transacción.

🐍 E3_0_race_condition.py 
import asyncio

saldo = 0

async def sumar_dinero():
    global saldo
    temp = saldo  # Leemos
    # Simulamos que el banco hace I/O y cede el control a otra tarea mientras suma
    await asyncio.sleep(0.01) 
    saldo = temp + 10  # Escribimos sobre una memoria desactualizada

async def main():
    tareas = [sumar_dinero() for _ in range(100)]
    await asyncio.gather(*tareas)
    print(f"Saldo Final esperado: 1000")
    print(f"Saldo Final real: {saldo}")  

asyncio.run(main())
Desastre financiero: Deberías tener 1000, pero acabas con 10. Como todas las tareas leen "0" antes de sumar "10" (porque se pausan en el `await`), todas terminan escribiendo "10". ¡Oops!

E3.1: El Guardia de Seguridad (Lock)

Objetivo: Usar `asyncio.Lock()` para garantizar exclusión mutua. Mientras alguien tiene el Lock, los demás esperan educadamente.

🐍 E3_1_lock_seguro.py 
import asyncio

saldo = 0
banco_lock = asyncio.Lock()

async def sumar_dinero():
    global saldo
    # Todo bloque dentro del async with está protegido contra otras tareas concurrentes
    async with banco_lock:
        temp = saldo 
        await asyncio.sleep(0.01) # I/O seguro
        saldo = temp + 10  

async def main():
    tareas = [sumar_dinero() for _ in range(100)]
    await asyncio.gather(*tareas)
    print(f"Saldo Final esperado: 1000")
    print(f"Saldo Final protegido con Lock: {saldo}")  

asyncio.run(main())
Magia: Al usar el async with lock, estás forzando a que la transacción sea serializada (una tras otra). Con esto evitas la sobreeescritura y logras los 1000.

E3.2: La Discoteca Limitada (Semaphore)

Objetivo: A veces no quieres limitar el acceso a *una sola persona* (Lock), sino a un número N de personas concurrentes. Se usa un Semáforo, ideal para no tumbar la API a la que llamas.

🐍 E3_2_semaphore.py 
import asyncio

# Solo caben 3 clientes concurrentes
limite_peticiones = asyncio.Semaphore(3)

async def descargar_video(video_id):
    async with limite_peticiones:
        print(f"[{video_id}] Dentro de la zona roja. Descargando...")
        await asyncio.sleep(1) # Simulación
        print(f"[{video_id}] Fuera. Dejando hueco libre.")

async def main():
    # Hay 10 videos por bajar, pero nuestro Semáforo solo permite procesar en bloques de 3
    tareas = [descargar_video(i) for i in range(1, 11)]
    print("Manejando 10 peticiones a la vez...")
    await asyncio.gather(*tareas)

asyncio.run(main())
El Semáforo es tu mejor amigo cuando tienes bucles masivos asíncronos (`fetch` a 10.000 urls). Si no usas un Semáforo, abrirías 10.000 sockets a la vez a nivel de SO y causarías un error Too many open files o un ban por parte del servidor destino.
