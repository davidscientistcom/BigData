Bloque 2: Controlando Tareas

Hasta ahora hemos esperado que todas las tareas terminen (`gather`). ¿Pero qué pasa si queremos lanzarlas en segundo plano (Fire & Forget), o cancelarlas si tardan demasiado?

E2.0: Disparar y olvidar (create_task)

Objetivo: Ver cómo planificar una tarea sin tener que usar `await` inmediatamente sobre ella. Muy útil para iniciar procesamiento en "background".

🐍 E2_0_create_task.py 
import asyncio

async def tarea_fondo():
    print("[Background] Tarea iniciada.")
    await asyncio.sleep(2)
    print("[Background] Tarea terminada. (No verás esto si el main termina primero)")

async def main():
    print("[Main] Planificando tarea en segundo plano...")
    # Creamos la tarea, se encola en el Event Loop
    tarea = asyncio.create_task(tarea_fondo())
    
    print("[Main] Haciendo otras cosas por 1 segundo...")
    await asyncio.sleep(1)
    
    print("[Main] Main a punto de terminar.")
    # Si terminamos main() el Event Loop se cierra. 
    # Comenta la línea de abajo para ver la diferencia.
    # await tarea  

asyncio.run(main())
Juega: Si ejecutas el código como está, verás "Main a punto de terminar" y el script morirá antes de imprimir que el Background ha terminado. `create_task()` planifica, pero si el loop principal muere, la tarea muere.

E2.1: El Cronómetro Implacable (Timeouts)

Objetivo: Las APIs fallan y las bases de datos se cuelgan. Aprenderemos a imponer límites de tiempo con `asyncio.wait_for()`.

🐍 E2_1_timeouts.py 
import asyncio

async def peticion_api_lenta():
    print("[Petición] Consultando API externa...")
    await asyncio.sleep(5)  # El servidor no responde rápido
    return "Datos de la API"

async def main():
    try:
        print("Lanzando petición con límite de 2 segundos...")
        # Imponemos un timeout. Si pasa 2 segundos, lanza TimeoutError
        resultado = await asyncio.wait_for(peticion_api_lenta(), timeout=2.0)
        print(f"Resultado: {resultado}")
    except asyncio.TimeoutError:
        print("🚨 CRÍTICO: La petición a la API excedió el tiempo máximo. Cancelando...")

asyncio.run(main())
Observa: La corrutina `peticion_api_lenta` se interrumpe de forma limpia al llegar a los 2 segundos. Python se encarga de inyectar una excepción en el punto de `await asyncio.sleep()` para matarla.

E2.2: Cancelación Fina y Limpieza (Graceful Shutdown)

Objetivo: Qué hacer cuando una tarea es cancelada por Timeout (o manualmente). A veces necesitas asegurar que cierras la conexión a la red antes de morir.

🐍 E2_2_cancelacion.py 
import asyncio

async def trabajo_delicado():
    print("▶️ [Worker] Abriendo conexión a base de datos...")
    try:
        print("▶️ [Worker] Trabajando (podría tardar 10 segundos)...")
        await asyncio.sleep(10)
        print("▶️ [Worker] Trabajo completado.")
    except asyncio.CancelledError:
        print("⚠️ [Worker] ME HAN CANCELADO! Limpiando sesión...")
        await asyncio.sleep(0.5) # Tiempo para limpiar
        print("✅ [Worker] Sesión cerrada de forma segura.")
        raise  # Es buena práctica relanzar la cancelación si se intercepta

async def main():
    tarea = asyncio.create_task(trabajo_delicado())
    
    await asyncio.sleep(2)
    print("🛑 [Main] El usuario ha pulsado el botón de cancelar. Cancelando trabajador.")
    tarea.cancel()
    
    try:
        await tarea
    except asyncio.CancelledError:
        print("🛑 [Main] Tarea confirmada como cancelada.")

asyncio.run(main())
Capturar `asyncio.CancelledError` es vital en arquitecturas robustas. Te da la oportunidad final de cerrar archivos, conexiones TCP o deshacer transacciones antes de que la función sea destruida del stack de ejecución.
