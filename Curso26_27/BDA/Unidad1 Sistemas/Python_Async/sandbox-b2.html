Bloque 02 · Planificación y Resiliencia

Ciclo de Vida de Tareas, Timeouts y Cancelación

Planificación de corrutinas concurrentes mediante Tasks, cumplimiento estricto de SLA con tiempos límite y liberación determinista de recursos.

E2.0: Planificación en Background (asyncio.create_task)

Objetivo Técnico: Encolar la ejecución inmediata de una corrutina en el bucle de eventos como un objeto Task sin suspender la ejecución de la función invocadora, facilitando el procesamiento en segundo plano.

python — e2_0_create_task.py 
import asyncio

async def worker_background():
    print("[WORKER] Tarea de background iniciada.")
    await asyncio.sleep(2)
    print("[WORKER] Tarea de background finalizada con éxito.")

async def main():
    print("[MAIN] Planificando tarea en el Event Loop...")
    # create_task agenda la corrutina; comienza en el siguiente yield del loop
    tarea = asyncio.create_task(worker_background())
    
    print("[MAIN] Ejecutando trabajo complementario (1.0s)...")
    await asyncio.sleep(1.0)
    
    print("[MAIN] Función principal próxima a terminar.")
    # Si se omite await tarea, el loop se destruye al salir de main()
    await tarea

if __name__ == "__main__":
    asyncio.run(main())
Regla Operativa: Al invocar asyncio.create_task(), la corrutina queda agendada inmediatamente en la cola de tareas listas del bucle. Sin embargo, si el punto de entrada principal (main()) retorna sin esperar la tarea ni persistir su referencia, el recolector de basura o el cierre del bucle abortarán su ejecución.

E2.1: Control de Latencia y Límites Temporales (asyncio.wait_for)

Objetivo Técnico: Implementar mecanismos de protección de SLA. En arquitecturas distribuidas, una llamada de red que no responda debe cancelarse antes de agotar los recursos del cliente mediante asyncio.wait_for().

python — e2_1_timeouts.py 
import asyncio

async def consultar_servicio_remoto():
    print("[NET] Emitiendo petición a servicio downstream...")
    await asyncio.sleep(5.0)  # Simulación de cuello de botella en red
    return {"status": 200, "data": "OK"}

async def main():
    try:
        print("[CLIENT] Invocando con timeout máximo de 2.0 segundos...")
        resultado = await asyncio.wait_for(consultar_servicio_remoto(), timeout=2.0)
        print(f"[CLIENT] Respuesta: {resultado}")
    except asyncio.TimeoutError:
        print("[ERROR] Timeout excedido: la petición superó el límite de 2.0s y ha sido cancelada.")

if __name__ == "__main__":
    asyncio.run(main())
Mecanismo Interno: Al alcanzar el umbral de timeout, asyncio.wait_for() no solo eleva una excepción TimeoutError en el invocador, sino que envía una señal de cancelación inmediata (task.cancel()) a la corrutina interna, evitando el consumo residual de memoria y CPU.

E2.2: Manejo de Cancelación y Limpieza Limpia (Graceful Shutdown)

Objetivo Técnico: Capturar la excepción asyncio.CancelledError en procesos de larga duración para garantizar la liberación determinista de descriptores, conexiones y recursos antes de confirmar la parada.

python — e2_2_graceful_shutdown.py 
import asyncio

async def transaccion_estado():
    print("[TRANSACTION] Apertura de socket y reserva de recursos...")
    try:
        print("[TRANSACTION] Procesamiento transaccional en curso...")
        await asyncio.sleep(10.0)
        print("[TRANSACTION] Procesamiento completado sin incidencias.")
    except asyncio.CancelledError:
        print("[WARN] Señal de cancelación detectada. Ejecutando rollback y cierre de sesión...")
        await asyncio.sleep(0.3)  # Liberación de recursos
        print("[CLEANUP] Rollback completado y socket cerrado correctamente.")
        raise  # CRÍTICO: Relanzar siempre para confirmar la cancelación al framework

async def main():
    tarea = asyncio.create_task(transaccion_estado())
    
    await asyncio.sleep(1.5)
    print("[SUPERVISOR] Señal de parada recibida. Cancelando tarea activa...")
    tarea.cancel()
    
    try:
        await tarea
    except asyncio.CancelledError:
        print("[SUPERVISOR] Tarea confirmada en estado CANCELLED.")

if __name__ == "__main__":
    asyncio.run(main())
Buenas Prácticas de Ingeniería: Si interceptas CancelledError para tareas de limpieza, es imprescindible ejecutar raise al final del bloque. Silenciar la excepción impide que el orquestador registre la tarea como debidamente cancelada y puede generar bloqueos en cascada.
