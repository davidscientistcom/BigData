Bloque 1: El Despertar del Event Loop

Antes de diseñar arquitecturas (M2), hay que entender qué significa ceder el control. Ejecuta estos scripts para entender la diferencia fundamental entre bloquear el mundo y pausar una tarea.

E1.0: El Falso Asincronismo (time.sleep)

Objetivo: Ver con tus propios ojos cómo funciones síncronas bloquean el Event Loop y rompen la concurrencia. No hay magia, si bloqueas el "hilo de eventos", nada avanza.

🐍 E1_0_falso_async.py 
import asyncio
import time

async def tarea_lenta_falsa(id_tarea):
    print(f"[Tarea {id_tarea}] Empezando trabajo...")
    # ❌ ESTO BLOQUEA TODO EL EVENT LOOP
    time.sleep(2) 
    print(f"[Tarea {id_tarea}] Trabajo terminado.")

async def main():
    print("Iniciando Event Loop...")
    # Intentamos ejecutar dos tareas "al mismo tiempo"
    await asyncio.gather(
        tarea_lenta_falsa(1),
        tarea_lenta_falsa(2)
    )
    print("Todo listo.")

if __name__ == "__main__":
    tiempo_inicio = time.time()
    asyncio.run(main())
    print(f"Tiempo total: {time.time() - tiempo_inicio:.2f} segundos")
Prueba esto: Ejecuta el código. Aunque uses `asyncio.gather()`, la ejecución tardará 4 segundos. El hilo principal se congela en `time.sleep()`, impidiendo que la Tarea 2 arranque mientras la Tarea 1 duerme.

E1.1: El Asincronismo Real (asyncio.sleep)

Objetivo: Reemplazar el bloqueo con "ceder el paso". Entender el uso fundamental de `await`.

🐍 E1_1_verdadero_async.py 
import asyncio
import time

async def tarea_lenta_real(id_tarea):
    print(f"[Tarea {id_tarea}] Empezando trabajo...")
    # ✅ ESTO CEDE EL CONTROL AL EVENT LOOP
    await asyncio.sleep(2) 
    print(f"[Tarea {id_tarea}] Trabajo terminado.")

async def main():
    print("Iniciando Event Loop...")
    await asyncio.gather(
        tarea_lenta_real(1),
        tarea_lenta_real(2)
    )
    print("Todo listo.")

if __name__ == "__main__":
    tiempo_inicio = time.time()
    asyncio.run(main())
    print(f"Tiempo total: {time.time() - tiempo_inicio:.2f} segundos")
Resultado: Ejecuta el código. Ahora tarda solo 2 segundos. Cuando la Tarea 1 hace `await asyncio.sleep(2)`, le devuelve el volante al Event Loop, que inmediatamente arranca la Tarea 2.

E1.2: El Bucle de Vida (Simulación de I/O)

Objetivo: Ver cómo se comportan 3 tareas de duraciones distintas cuando concurren.

🐍 E1_2_multi_tiempos.py 
import asyncio

async def descargar_archivo(nombre, segundos):
    print(f"[{nombre}] Empezando descarga...")
    await asyncio.sleep(segundos)
    print(f"[{nombre}] Descarga finalizada! ({segundos}s)")
    return f"Contenido_{nombre}"

async def main():
    print("Iniciando descargas concurrentes...")
    resultados = await asyncio.gather(
        descargar_archivo("Video", 3),
        descargar_archivo("Imagen", 1),
        descargar_archivo("Texto", 0.5)
    )
    print(f"Resultados recolectados en el mismo orden: {resultados}")

asyncio.run(main())
Observa: El "Texto" termina primero, luego "Imagen", y por último "Video". Sin embargo, `asyncio.gather` te devuelve la lista de resultados ['Contenido_Video', 'Contenido_Imagen', 'Contenido_Texto'] en el orden que le pasaste inicialmente, agrupando mágicamente el desorden del I/O concurrent.
